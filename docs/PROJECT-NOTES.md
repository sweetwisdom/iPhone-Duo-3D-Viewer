# 项目难点与亮点

## 技术难点

### 官网资源并非可直接运行的 Three.js 工程

页面资源来自网络抓包，原始实现依赖 Apple 的 Lotus 运行时、按哈希命名的资源，以及分散在多个 `.lsd` 文件中的场景与材质配置。项目没有直接执行官网页面脚本，而是通过资源清单按名称查找资源，并为壁纸模块提供最小 Three.js 适配层，避免引入页面入口、分析代码和无关依赖。

### 折叠动画需要忠实映射

模型包含 81 条轨道的 `Slider` 动画。展示不能只旋转两个面板，而要以动画时间驱动铰链、屏幕和机身全部关联节点；同时还需要将滑块值、动画时间、机身位置和壁纸状态保持同步，才能在合拢、中间与完全展开之间连续过渡。

### 屏幕是动态合成结果

内外屏画面不是一张固定纹理：壁纸由多层 glTF 场景渲染，叠加锁屏 UI 后再进行边框处理与模糊。屏幕材质还需要依据开合程度应用原始擦除逻辑，才能呈现折叠时的亮度、遮罩和过渡效果。

### 机身材质与层次遮挡

官网使用多组环境资源和遮罩定义控制反射及局部遮挡。将其迁移到标准 Three.js 时，需要生成 PMREM 环境贴图、映射材质层级、校准珍珠白背板的粗糙度与反射，并用模板缓冲的显式渲染通道复刻屏幕和机身的遮挡关系。

## 项目亮点

- **基于真实资源还原**：使用官网 glTF、开合动画、壁纸、UI、环境和遮罩资源，而非通用折叠手机模型。
- **拆分清晰的渲染职责**：模型动画、资源加载、壁纸生成、屏幕着色、环境材质和遮罩通道各自独立，便于定位和继续调优。
- **连续且可访问的交互**：支持鼠标／触控拖动、范围滑块、姿态预设与键盘快捷键；禁用动画偏好会立即完成开合。
- **嵌入友好**：`?isolated` 可隐藏页面装饰，只保留三维展示与控制区；`?fold=` 能指定初始开合状态。
- **有可重复的视觉检查路径**：检查脚本能产出多种开合状态与背部视角截图，用于回归比对。

## 还原边界

项目复用的是提供的官网资源，但渲染器为独立的 Three.js 实现。不同浏览器、GPU、色彩管理和光照模型会造成轻微的反射、抗锯齿或色彩差异；页面目标是还原产品展示的模型、状态、层次与交互，而非复制官网的完整运行时。
